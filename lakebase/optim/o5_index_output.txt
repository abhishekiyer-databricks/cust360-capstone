CONCLUSION
----------
The <200 ms list-endpoint target is already met with a Seq Scan (~4 ms server-side), so the
index is not needed. Recommendation: DROP the inert index — on a CONTINUOUS synced table it
adds write/maintenance cost on every sync update for zero read benefit. If exact-match segment
filtering is later adopted (the dropdown already emits exact ids) AND the table grows large,
revisit with `segment_id = %s` + this index.
